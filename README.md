# ECU Log Viewer

The application opens supported `.mlg` binary logs locally on Linux and in a browser. With no log loaded, use the centered **Open log…** button. Once a log is open, its filename and available summary metadata appear together in the status row. Browser files stay on the device. Failed loads preserve the previous log. Use the full-width timeline to drag the playhead, or drag its range handles to limit the time-series and RPM/MAP plots to a specific interval. Exact range endpoints are editable below the timeline; **Full log** restores the complete interval. Playback and plotted coordinates use recorded timestamps and samples only. The left panel contains searchable field values; each **+** button adds that numeric field to the central **Gauges** tab. The central panel has fixed **Gauges** and **Plots** tabs above its scrollable content. VE and AFR/scatter views are stacked in equally sized regions in the right panel, with tabs to switch between the AFR table and scatter plot. Play, pause, seek, and change speed with the transport controls. Space toggles playback; Left/Right seek ten seconds; Home/End seek to the bounds when a text field or control is not focused. Configure gauge scale, nominal and warning limits, precision, size, and order. Gauge settings persist where application storage is available. The battery-voltage preset is illustrative and can be edited. Time-series groups support overlay and stacked views, per-series left/right Y axes, linked horizontal pan and zoom, and hover inspection of the underlying recorded sample. Table and field values round to three significant figures for display; hover for the full parsed value. Repeated RPM breakpoints are displayed once, retaining the first matching table column; the viewer reports how many later duplicate columns it skipped.

The supported container and known limitations are described in [log-format.md](docs/log-format.md). The original `.mlg` capture is ignored by Git because it contains private metadata; `tests/fixtures/sanitized.mlg` retains its field descriptors with synthetic sample values and no tune or capture metadata.

Use `nix develop` for the pinned development shell, `nix run` for the desktop application, `nix build` for the native package, `nix build .#web` for the web bundle, `nix run .#web-dev` for local web development, and `nix flake check` for the complete checks, including a local headless-browser smoke test. To validate the private full fixture locally, run `LOG_VIEWER_FIXTURE=/path/to/file.mlg nix develop --command cargo test --test parser local_original_fixture_when_requested`. To measure native loading/parsing, run `nix develop --command cargo run --release --example measure -- /path/to/file.mlg`.

The browser smoke build and its automation tools are provided by Nix. It imports a local fixture through a test-only hook into the same parser and load pipeline, verifies row selection after seeking, checks both dashboard map panels, and fails on fatal browser errors. The hook avoids the native browser chooser, which crashes in this Nix build sandbox; the actual picker was exercised locally with the supplied capture. The browser parses on its main thread, so large files can briefly block rendering. The committed fixture is intentionally tiny and is only a behavior check, not a performance proxy. Use the measurement command and the local browser harness with the original capture for machine-specific results; see [performance notes](docs/performance.md) and the [dependency audit process](docs/security.md).

For highly fragmented time series with more disconnected runs than the plot budget, some runs are omitted while visible minima and maxima remain shown; playback and analysis retain every sample. Plot groups, gauge settings, map display preferences, the AFR/scatter tab, theme, and playback speed are persisted where storage is available. Settings are versioned; use **Reset all settings** to clear the current layout.

The static-site publishing workflow deploys only after successful default-branch checks. Configure the repository's hosting settings to use the automated deployment workflow once. Pull requests do not deploy. The uploaded artifact is only the output of `nix build .#web`; no input logs are included. Advisory data is pinned in `flake.lock`; update it with `nix flake lock --update-input advisory-db`, review the audit output, and rerun `nix flake check` before committing the new lock.
